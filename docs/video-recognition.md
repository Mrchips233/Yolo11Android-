# 导入视频与逐帧检测

首页点击「导入视频 · 逐帧识别」，使用系统文件选择器选择视频，再选择一个可写的导出文件夹。建议在 Download 中新建子目录。选择 960 或 640 输入模式和可用推理后端，点击「开始逐帧识别」。此功能不需要高德 Key 或 GPS。

处理使用 MediaExtractor / MediaCodec 连续解码视频轨道，再逐帧调用与实时相机相同的 ncnn 检测模型。不会按时间间隔抽样，也不会按标称 FPS 推算时间；使用实际解码帧的 presentation timestamp。每帧识别完成后立即保存，不在内存中积累整段视频。

每次任务创建独立结果目录，包含：

- 每个已完成帧的 JPEG 标记图。框、类别代码和置信度绘制在转正后的画面上；无检测目标时仍保存该帧。
- UTF-8 BOM 编码的 CSV 表格，可由 Excel / WPS 打开。一个目标占一行，同帧多个目标重复对应图片名；无目标帧也有记录。
- `run.json` 记录运行状态、处理帧数与配置信息。完成、取消和失败必须区分，部分结果不能当作整段处理成功。

「在视频中的位置」指帧号和视频时间，不代表地理坐标。帧号从 1 开始；原始解码 PTS 与相对首帧的时间分别保存。检测框为转正后导出图片的像素坐标，坐标原点在左上角。类别使用 `tt100k45.labels.txt` 中的官方代码，保持与训练标签的含义和顺序一致。

| CSV 字段 | 含义 |
| --- | --- |
| `image_name` | 对应的标记图片名称 |
| `class_id`, `class_code` | 0 基模型类别索引与 TT100K 类别代码，无目标时为空 |
| `frame_index` | 1 基解码帧序号 |
| `timestamp_us`, `timestamp` | 原始解码 PTS（微秒）及可读时间 |
| `elapsed_us`, `elapsed_timestamp` | 相对首帧的时间（微秒）及可读时间，便于在播放器定位 |
| `confidence` | 模型置信度，不是经人工验证的正确率 |
| `x1`, `y1`, `x2`, `y2` | 导出图片中检测框左上及右下的像素坐标 |
| `source_width`, `source_height` | 转正并裁切后的导出图片尺寸 |
| `frame_status` | 有检测目标或无检测目标的记录状态 |

请保持处理页面在前台。点击取消、离开页面或关闭应用会结束未完成处理；已写出的结果保留，取消需等待当前处理步骤结束。强制结束进程时可能无法更新 `run.json`，此时其中的运行中状态同样表示不完整。页面旋转不会重启任务。

全帧输出会产生大量图片。例如 1 分钟、30 FPS 视频约有 1800 帧，实际数量以解码结果为准。文件大小取决于分辨率和内容，建议先用几秒视频确认设备速度、方向和磁盘占用。无可用解码器、无法读取授权文件、写入失败或存储不足时会报告错误并保留部分结果。当前为前台任务，没有后台长期运行服务。

CSV 和标记图适合人工复核、定位漏检或误检。模型预测不能代替人工真值，也不能仅凭置信度计算准确率。评价方法见 [手机检测准确度评价方案](mobile-accuracy-evaluation.md)。
