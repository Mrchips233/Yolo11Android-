# 手机端交通标志检测准确度评价方案

制定日期：2026-10-16。目标是回答：手机上识别对不对、漏了多少、空场景会不会乱报，以及 960 是否值得增加计算量。先做端上离线复验，再用独立真实场景盲测；帧率和发热另列，不能用运行正常或 FPS 代替准确度。

## 当前依据与边界

- 当前应用使用 YOLO11n TT100K45，45 类顺序以 `app/src/main/assets/tt100k45.labels.txt` 为准，模型及哈希见 `tt100k45.model.json`。
- 固定部署条件：置信度 **0.465**、按类别 NMS IoU **0.7**、每图最多 **300** 框；分别比较 CPU、GPU、Turnip 的 640/960。设备不支持的后端记录为“不支持”，不算精度失败。
- 本机派生 TT100K45 的 train/val/test 为 **5489/610/3071** 图；已排除官方 train/test 的 6 个同内容重复 ID。随机 val 未按路线分组，不能代替真实道路独立验证。
- 官方 test 已在模型冻结后做过一次验收，后续不得根据它选择阈值、模型或训练方案，也不再称其“完全未见”。历史报告在 `D:\Works\yolo_training\第二轮训练评价.md`；该报告的安卓未接入章节是当时状态，当前部署以 [模型部署记录](tt100k45-model.md) 为准。
- 已有 20 张 val、640/960 共 40 次 PyTorch/桌面 NCNN 对照，是导出数值一致性检查，只有 18 类保留预测；它没有覆盖全量标注，也不是 APK 的准确率测试。

## 一、先固定评测协议

运行前保存一份只读清单：APK/模型/标签 SHA256、Git 提交及未提交 diff、手机型号和系统版本、后端/驱动、输入尺寸、采集与裁剪尺寸、阈值、数据清单和哈希、标注版本、匹配与忽略规则、验收要求。六种配置使用相同数据和标注，不按某个配置的结果增删图片。

同一图像只算一个评测样本；重复运行用于稳定性检查，不能增加精度样本量。模型、阈值、预处理或代码发生影响预测的变化后生成新版本报告，保留旧结果。

## 二、端上离线复验：检查安卓部署有没有损失

1. 使用现有完整 **610 张 val 及其原始标注**，不重新训练、不调用官方 test。该集合用于部署回归，结果不称作新数据泛化能力。
2. 手机批量读取固定图片，调用与相机相同的 Native 检测函数，保存 `image_id、backend、input_size、class_id、score、x1/y1/x2/y2、原图尺寸、错误状态`。坐标以未画框的输入图像为准，浮点置信度不得只保留两位小数；即使没有检测框，也保存该图已处理记录。
3. 桌面 PyTorch 参考与手机使用**同一 RGB 像素、同一缩放插值、取整、114 补边、32 倍数对齐、归一化、解码、NMS 和坐标逆变换**。必要时直接保存手机预处理张量供参考模型运行。不能把桌面默认正方形 letterbox 与手机长边矩形输入直接作差，并把差异都归因于后端。
4. 全量计算下述标注对照指标，同时做同图预测配对，检查错类、框偏移、漏框和阈值附近的分数差。浮点数不要求逐位相同；关注是否改变检测结论。加载或推理失败必须列明，另外报告失败率，不能静默丢弃图片。

**本轮工具进展：**已新增视频流式逐帧推理与导出实现：每帧标记 JPEG、带 UTF-8 BOM 的 CSV（含帧号、原始 PTS/相对时间、类别、浮点置信度、框坐标、图像尺寸；空帧也记录）、完成/取消/失败状态清单；另有 JNI 单图仪器测试源码。视频工具只保存画框后的图，不能替代无叠加的原始评测输入。测试源码与功能实现不等于设备验证，本轮不安装测试 APK，也未完成手机准确度实测。

**仍待实现或执行：**610 张原图批量端上复验、无叠加原帧/预处理张量导出、低候选阈值 AP 通道、统一标注评测脚本和完整报告。相机业务 CSV 缺少逐图完整框及零检测记录，不能直接用于此项评价；视频 CSV 虽有这些字段，仍需完整人工 GT 才能算准确度。

## 三、手机真实场景盲测：检查实际使用是否可靠

### 两阶段采集与工作量

| 阶段 | 样本与用途 | 执行要求 |
|---|---|---|
| 试验 | 100～200 张独立场景图，含约 20%～30% 已确认无 45 类目标的图片 | 覆盖常见类别、远小目标、遮挡、逆光、夜晚，走通保存/标注/评测并暴露问题；允许用于开发，之后不再作为盲测 |
| 正式 | 另采 500～1000 张，含约 20%～30% 确认空图；按采集点和路线分组冻结 | 先完成标注与协议锁定，再一次性跑所有配置；不因看过预测而挑图或修改通过条件 |

以上是总图数目标，并不保证覆盖 45 类。正式报告必须列出每类图数、目标数、独立场景数；不足的类别明确写“证据不足”，零目标类写 N/A，不能写成 0% 或宣称全部合格。重点常见类可先争取每类至少 30 个目标、来自多个地点；30 也只够初步判断，少见类要额外定向采集并单列，不能改变真实场景总体分布的权重。

粗估人工框选和复核按每图 3～6 分钟计：试验约 5～20 小时，正式约 25～100 小时；采集、疑难类别和二人复核另计。可以先做 100 图试验决定是否值得扩大，不能用少量图直接宣布全 45 类准确度。

### 数据独立性与画面保存

- 优先保存手机**实际送入检测前、未叠加框的 RGB 画面**，保留相机旋转和中心裁剪后的尺寸。该原帧保存/采样通道待实现；普通拍照模式可能改变分辨率、HDR 和裁剪，只能作为补充离线数据。
- 按路线、地点、日期和同一块实体标志分组，开发集与正式集不得共用同一标志或相邻路段连续帧。视频先按场景/实体分组再抽帧，不能先随机分帧；一段连续靠近同一标志的视频不能当几十个独立样本。
- 先按采集计划定时/定点采样，再人工标注；不能只保存模型成功画框的画面。覆盖白天、夜间、顺光/逆光、阴影、模糊、遮挡和背景干扰，各组都给出数量；没采到的条件明确列为未评估。
- 距离只有测量或可靠记录时才报米数；其余使用输入中目标像素大小分层，不能凭视觉猜 20 米/50 米。视频若另测首次检出距离或持续漏检，应以同一标志的一次经过为单位，单列为事件指标。
- 新增视频工具逐帧输出标记图，以及含图片名、类别、帧序号、原始 PTS/相对时间、框坐标的表格，零检测帧也保留，可辅助人工抽检；仍需补完整人工 GT 与低分候选通道才能算标准完整 AP。相邻帧不能作为独立盲测样本。
- 采集和评测留在本机，不上传原始道路画面。记录相机视野外目标不会成为漏检；需要评价完整道路视野时另保存全帧和 ROI 映射，再单列因裁剪损失的目标。

### 标注规则

1. 先写类别代码判定手册，按 TT100K 官方类别定义标注；不凭代码猜中文含义。标注者先看原图，避免参考本模型的预测形成偏差。
2. 每张图穷尽标出**所有可判定的 45 类目标**，不是只框最显眼的一块。统一框住可见标志本体、紧贴边缘，不含杆和大块背景；遮挡、截断规则预先确定并记录。
3. 其他类别的真实交通标志不纳入 45 类 GT，作为范围外干扰物保留；模型若把它报成 45 类之一，计误报。不得把范围外标志映射到最相近的已知类。
4. 看不清类别、极端遮挡等疑难区域由第二人复核。确实无法判定时，按预先锁定的规则标记 ignore 并给出数量；只有符合事前规则的预测才可忽略，不能看到误报后临时排除区域。
5. “空图”表示经人工确认没有任何可评价的 45 类目标；空标签文件、官方 `other` 或肉眼第一眼未发现标志，都不是负例证据。空图至少复核一遍，防止漏标远小目标。

## 四、指标怎么算、怎么看

固定部署点先按置信度 0.465 过滤，再按类别、IoU≥0.5 一对一匹配；同一 GT 最多匹配一个预测。重复框计 FP，错类同时形成该预测的 FP 与真实类别的 FN。ignore 区域匹配和过滤顺序必须与冻结协议一致。

| 指标 | 含义与报告口径 |
|---|---|
| Precision = TP/(TP+FP) | 报出来的框有多少正确 |
| Recall = TP/(TP+FN) | 真实标志找到了多少 |
| F1 = 2PR/(P+R) | 固定工作点的折中；同时给微平均与按类宏平均，说明无支持类处理方式 |
| AP50、AP50-95 | 按分数排序的定位/分类能力；AP50-95 使用 IoU 0.50～0.95、步长 0.05，按标准评测器计算各类 AP 与 mAP |
| FP/image | 所有图和确认空图分别报告平均误报框数，并报“至少误报一次的空图比例” |
| 逐类与混淆 | 45 类 TP/FP/FN、P/R/F1/AP、样本量及常见错类，不能只给总体平均 |

**AP 需要额外的评测导出通道。**标准 AP 要保留足够低分候选，例如事前固定 `conf=0.001`，仍固定 NMS=0.7、max300，所有后端一致；这只用于计算完整 PR 曲线，不改变应用的部署阈值，也不能在盲测上重新挑工作点。若只有 0.465 后的预测，只报告固定点 P/R/F1，或明确标成“阈值截断 AP”，不得当作标准完整 AP 与历史报告比较。

分层至少包括目标大小、光照、遮挡和采集场景。大小同时报告**固定原始/ROI 坐标下的框面积或短边**及输入后像素大小；比较 640/960 时使用固定来源坐标的分组，避免同一目标因缩放被换组。若采用 COCO small/medium/large 面积分界，须说明坐标空间和非 COCO 数据口径。

所有主要指标给 95% 置信区间。建议按路线/场景组做 bootstrap（例如预先固定 seed、2000 次），配置差异用同组配对重采样；不能把相邻帧当独立样本套窄区间。报告组数与每类支持量，极小样本的宽区间照实保留。若 100 张独立空图零误报，误报图比例的 95% 上界仍约为 3%，不能声称不会误报。

## 五、比较与建议验收规则

同一套图完整运行 `CPU/GPU/Turnip × 640/960`，报告每配置的精度、失败率和相对 CPU 同尺寸的配对差异。960 与 640 的比较用于选择分辨率，不把它混成后端精度差。设备/驱动回退时必须记录实际后端。

下面只是**运行正式盲测前可选择并书面锁定的建议值**，尚不是本模型达成的结果，也不保证适合所有道路用途：

- 端上部署回归：相对同预处理桌面参考，同尺寸 mAP50-95 和固定点 F1 下降不超过 1 个百分点，且无系统性错类/坐标偏移。差异及 95% 区间都列出；区间过宽时结论为“不确定”。
- 初步实际体验目标：IoU=0.5、conf=0.465 时微平均 P≥90%、R≥80%，确认空图 FP/image≤0.05；同时审查关键类别与小目标分层，不让大量容易类别掩盖漏检。
- 对正式验收，可要求 P/R 的 95% 下界及 FP/image 的 95% 上界满足约定值。若图数/独立场景不足以收窄区间，应补采，不能通过改口径或事后调阈值变成通过。

正式数据看过结果后若用于改模型或阈值，就转成开发数据；下一版要另建盲测集。历史官方 test 只保留既有验收记录。

## 六、性能另表，最终交付

精度批处理每图必须真正完成推理；实时模式的跳帧不等于单图 FN，但会影响持续可用性。另测连续运行的有效检测 FPS、预处理/推理/后处理延迟 P50/P95、相机到结果延迟、丢帧率、切换停顿、温度/降频、内存与崩溃，固定采集尺寸和测试时长。不要把重复的同一帧推理次数当新检测帧。

最终交付保留冻结协议、图片清单与标注、逐图原始预测、逐类及场景表、置信区间、固定数量的误报/漏报/错类示例，以及独立性能表。先据端上复验排除移植问题，再据独立盲测判断采集/小目标/少样本类问题，后续修改以开发数据验证。
